# IPTV Overlay Server

[![GitHub](https://img.shields.io/badge/GitHub-andrey--geben%2FIPTV--Overlay--Server-blue?logo=github)](https://github.com/andrey-geben/IPTV-Overlay-Server)

Программа для организации IPTV-трансляции с наложением бегущих строк на выбранные каналы по расписанию.

Локальный HTTP-сервер, который:
- принимает плейлист M3U/M3U8 от провайдера;
- позволяет отобрать каналы для трансляции и наложить на них бегущие строки;
- раздаёт по сети модифицированный плейлист — клиент (VLC, TiviMate, Kodi, ТВ-приставка) получает уже обработанный поток.

**Репозиторий проекта:** [https://github.com/andrey-geben/IPTV-Overlay-Server](https://github.com/andrey-geben/IPTV-Overlay-Server)

## Возможности

- Загрузка плейлистов M3U/M3U8 от провайдера (поддержка UTF-8, cp1251, latin-1)
- Две ступени отбора каналов:
  - **Панель 1** — какие каналы попадут в трансляцию (то есть в исходящий плейлист)
  - **Панель 2** — на какие из них наложить бегущую строку
- Автоматическое скачивание FFmpeg при первом запуске (если он не найден в системе)
- Локальный HTTP-сервер на FastAPI
- Гибкая настройка бегущей строки:
  - Произвольный текст
  - Шрифт — системный или выбранный `.ttf`/`.otf`
  - Размер шрифта
  - Цвет текста и его прозрачность (α 0–255)
  - Цвет фона и его прозрачность (вплоть до полностью прозрачного)
  - Скорость прокрутки (пикс/сек)
  - Периодичность прогона — раз в N минут
- Расписание:
  - Дата начала и (опционально) дата окончания
  - Время старта и стопа
  - Дни недели (галочки Пн–Вс)
- Несколько одновременных бегущих строк на разных каналах
- Копирование URL исходящего плейлиста в буфер обмена
- Сохранение исходящего плейлиста в файл
- Просмотр содержимого исходящего плейлиста
- Встроенная справка (F1) и диалог «О программе»

## Требования

- **Python 3.10+**
- **Windows**, **Linux** или **macOS**
- **FFmpeg** — скачается автоматически при первом запуске; если он уже установлен в PATH, будет использован системный
- Свободный порт **8000**
- Доступ к **github.com** при первом запуске (для загрузки FFmpeg, ~150 МБ)

## Установка

### 1. Получите проект

Клонируйте репозиторий:

```bash
git clone https://github.com/andrey-geben/IPTV-Overlay-Server.git
cd IPTV-Overlay-Server
```

Либо скачайте ZIP-архив со страницы релизов и распакуйте.

### 2. Создайте виртуальное окружение (рекомендуется)

**Windows:**

```cmd
python -m venv .venv
.venv\Scripts\activate
```

**Linux / macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установите зависимости

```bash
pip install -r requirements.txt
```

Содержимое `requirements.txt`:

```text
PyQt6
fastapi
uvicorn
apscheduler
```

### 4. Запустите

```bash
python main.py
```

При первом запуске программа:

1. Проверит наличие FFmpeg в системе.
2. Если не найдёт — скачает статическую сборку в папку `ffmpeg_bin/`.
3. Откроет главное окно.

## Быстрый старт

1. Нажмите **«Загрузить M3U»** и выберите файл от провайдера.
2. В панели **«1. Входящий плейлист»** отметьте каналы, которые пойдут в трансляцию.
3. В панели **«2. Трансляция»** отметьте те каналы, на которые нужна бегущая строка.
4. В панели **«3. Настройки бегущей строки»** заполните текст, шрифт, цвета, скорость, период и расписание.
5. Нажмите **«Добавить оверлей в расписание»**.
6. Нажмите **«Запустить сервер»**.
7. Скопируйте URL из блока «Исходящий плейлист» и откройте его в VLC или другом IPTV-плеере.

## Использование

### 1. Загрузка плейлиста

Кнопка **«Загрузить M3U»** — открывает диалог выбора файла. Поддерживаются расширения `.m3u` и `.m3u8`. При загрузке программа автоматически определяет кодировку файла.

Загруженные каналы появятся в панели **«1. Входящий плейлист»** — пока без галочек.

### 2. Две ступени отбора

**Панель 1 — «Входящий плейлист»**

- Здесь все каналы, полученные от провайдера.
- Галочка = канал попадёт в **исходящий плейлист** и будет доступен клиенту.
- Кнопки:
  - **«Выбрать всё»** — отметить все каналы
  - **«Снять всё»** — снять все отметки
  - **«Удалить»** — удалить выбранный канал из плейлиста насовсем

**Панель 2 — «Трансляция»**

- Заполняется автоматически из отмеченных в панели 1.
- Здесь свои галочки: если отмечен — на канал будет наложена бегущая строка.
- Если канал транслируется, но здесь не отмечен — зритель получит **чистый поток провайдера** без оверлея.

### 3. Настройка бегущей строки

Все параметры задаются в панели **«3. Настройки бегущей строки»**:

| Поле | Описание |
|------|----------|
| **Текст** | Что будет отображаться |
| **Шрифт** | Кнопка «…» открывает выбор `.ttf`/`.otf`. Пусто = системный Arial |
| **Размер шрифта** | В пикселях, 8–200 |
| **Цвет текста** | Кнопка «Выбрать цвет…» открывает системный Windows-диалог |
| **α текста** | Прозрачность текста, 0–255 |
| **Фон** | Включить/выключить подложку |
| **Цвет фона** | Кнопка «Цвет фона…» — тот же системный диалог |
| **α фона** | Прозрачность фона, 0–255. **α=0 — фон полностью прозрачный** |
| **Раз в (мин)** | Периодичность прогона. 20 = строка пробегает раз в 20 минут |
| **Скорость (px/s)** | Чем больше, тем быстрее движется текст. 100 = умеренно |
| **С даты** | Календарь — дата начала действия расписания |
| **По дату** | Чекбокс + календарь — дата окончания (опционально) |
| **Старт / Стоп** | Время начала и конца показа в течение дня |
| **Дни недели** | Галочки Пн–Вс. По умолчанию все включены |

После заполнения — **«Добавить оверлей в расписание»**. Оверлей появится в левой колонке в блоке «Запланированные оверлеи».

### 4. Запуск сервера

Кнопка **«Запустить сервер»**:

- Поднимает FastAPI + Uvicorn на `0.0.0.0:8000`
- В блоке «Исходящий плейлист» появляется URL вида `http://192.168.1.10:8000/playlist.m3u`
- Кнопки «Копировать», «Сохранить…», «Показать содержимое» работают с этим плейлистом

### 5. Просмотр в клиенте

Откройте URL в любом IPTV-плеере:

- **VLC** → «Медиа» → «Открыть URL» → вставьте ссылку
- **TiviMate / Kodi** → добавьте плейлист по URL
- **ТВ-приставка** → введите URL вручную

**Что увидит клиент:**

- **Канал без оверлея** — сервер отвечает HTTP 302 и перенаправляет на оригинальный поток провайдера (без нагрузки на CPU).
- **Канал с активной бегущей строкой** — сервер отдаёт HLS-поток, подготовленный FFmpeg с наложенным текстом.
- **Канал с оверлеем вне активного окна** — сервер также перенаправляет на оригинал, оверлей не виден.

### 6. Управление оверлеями

В левой колонке в блоке **«Запланированные оверлеи»** — список всех созданных оверлеев. Каждая запись содержит:

- ID оверлея
- Номера каналов
- Текст
- Даты и время
- Периодичность
- Скорость
- Размер шрифта
- Название шрифта

Кнопка **«Удалить выбранный оверлей»** — удаляет оверлей и останавливает его FFmpeg-процессы, если они активны.

### 7. Меню

- **Файл → Выход** (`Ctrl+Q`) — завершение работы
- **Справка → Руководство пользователя** (`F1`) — открывает этот README во встроенном просмотрщике
- **Справка → О программе** — диалог с версией, автором и лицензией

## Как это работает

### Архитектура

```
+--------------+        +--------------+        +--------------+
|   Клиент     |------->|   FastAPI    |------->|   Провайдер  |
|  (VLC / ТВ)  |<-------|   Uvicorn    |<-------|    (IPTV)    |
+--------------+        +------+-------+        +--------------+
                               |
                  +------------+------------+
                  |                         |
          +-------v--------+        +-------v--------+
          |   FFmpeg       |        |   Redirect     |
          |  (с оверлеем)  |        | (без оверлея)  |
          +-------+--------+        +----------------+
                  |
          +-------v--------+
          |  HLS-сегменты  |
          |  /hls_output/  |
          +----------------+
```

### Логика запросов

1. Клиент запрашивает `GET /playlist.m3u`
2. Сервер возвращает M3U только с отмеченными в панели 1 каналами
3. Клиент выбирает канал и запрашивает `GET /stream/{id}/index.m3u8`
4. Сервер проверяет, запущен ли FFmpeg для этого канала:
   - **Запущен** → отдаёт `index.m3u8` и сегменты `segment_NNN.ts` из `hls_output/{id}/`
   - **Не запущен** → отвечает HTTP 302 Redirect на оригинальный URL провайдера

### Логика FFmpeg

- Для каждого канала с активным оверлеем запускается отдельный процесс FFmpeg
- Процесс читает поток провайдера (`-re` — в реальном времени)
- Накладывает текст через фильтр `drawtext` с функцией `mod(t*speed, period*speed)` для периодического прогона
- Пишет HLS-сегменты (2 сек) в `hls_output/{id}/`
- APScheduler запускает и останавливает процессы по расписанию

### Логика расписания

- `CronTrigger` с `day_of_week` — для дней недели
- Проверка `start_date`/`end_date` при каждом срабатывании
- При создании оверлея, если момент попадает в активное окно — `DateTrigger` запускает задачу через 1 секунду в фоновом потоке

## Параметры бегущей строки

### Как работает периодический прогон

В фильтре FFmpeg используется выражение:

```text
x = w - mod(t * speed, period * speed)
```

Где:

- `t` — текущее время в секундах
- `speed` — скорость прокрутки (px/s)
- `period` — период повтора в секундах

**Что это даёт:**

| Момент | Позиция текста |
|--------|----------------|
| `t = 0` | Справа за экраном |
| `t = (W + L) / speed` | Ушёл за левый край (W — ширина экрана, L — ширина текста) |
| `t = period` | Снова справа — цикл повторился |
| Между прогонами | Не виден (находится «за кадром») |

**Пример:** `period=1200` (20 мин), `speed=100` px/s, экран 1920 px:

- Один прогон занимает ~20 секунд
- Раз в 20 минут строка пробегает справа налево
- Остальное время не видна

### Проверка «успеет ли строка пробежать»

При добавлении оверлея программа проверяет:

```text
speed * period >= (1920 + len(text) * font_size * 0.6)
```

Если не выполняется — показывает предупреждение. Это значит, что строка не успеет полностью пробежать за один период, и её «хвост» может быть обрезан.

**Решения:**

- Увеличить скорость
- Увеличить период
- Сократить текст

### Цвета в FFmpeg

Формат цвета в фильтре `drawtext`:

- Без прозрачности: `0xRRGGBB` (например, `0xFFFF00` — жёлтый)
- С прозрачностью: `0xRRGGBB@A`, где `A` — от 0.0 до 1.0

Программа преобразует α (0–255) в эту шкалу автоматически: `α=153` → `@0.60`.

### Шрифты

- **Системный по умолчанию**: Windows — Arial, Linux/macOS — DejaVu Sans
- **Пользовательский**: любой `.ttf` или `.otf` файл
- **Путь экранируется** для FFmpeg: `C:/Windows/Fonts/arial.ttf` → `C\:/Windows/Fonts/arial.ttf`

**Рекомендация:** используйте шрифты из `C:\Windows\Fonts\` — они гарантированно доступны FFmpeg и не содержат кириллицы в пути.

## Решение проблем

### FFmpeg не скачивается автоматически

**Симптом:** в консоли ошибка загрузки, или красная надпись «FFmpeg не найден».

**Решение:**

1. Проверьте доступ к `github.com`
2. Установите FFmpeg вручную:
   - **Windows:** `winget install Gyan.FFmpeg`
   - **Linux:** `sudo apt install ffmpeg`
   - **macOS:** `brew install ffmpeg`
3. Перезапустите программу — она найдёт системный FFmpeg в PATH

### Оверлей не появляется

**Симптом:** канал воспроизводится, но без текста.

**Диагностика:** откройте `hls_output/{id}/ffmpeg.log` — там будет точная ошибка.

**Частые причины:**

| Ошибка в логе | Причина | Решение |
|---------------|---------|---------|
| `Cannot find a valid font` | Шрифт не найден | Выберите `.ttf` из `C:\Windows\Fonts\` |
| `Unable to parse option value` | Спецсимволы в тексте | Замените `%`, `\`, `[`, `]` на другие |
| `No such filter: drawtext` | FFmpeg собран без libfreetype | Установите полную сборку (Gyan.FFmpeg подходит) |
| `Cannot open connection` | Поток провайдера недоступен | Проверьте URL провайдера в VLC напрямую |

### Видео тормозит / высокий CPU

**Причина:** каждый активный оверлей — отдельный перекодирующий процесс FFmpeg.

**Решения:**

- Ограничьте количество одновременных оверлеев (1–2 на слабом ПК)
- Снизьте разрешение: добавьте `scale=1280:-2` перед `drawtext` в фильтре
- Используйте более производительный пресет (по умолчанию `ultrafast` — уже минимальный)
- Если провайдер отдаёт H.264 — можно попробовать `-c:v copy`, но тогда `drawtext` не сработает

### Клиент не может подключиться

**Симптом:** VLC с другого устройства не открывает плейлист.

**Проверьте:**

1. **Брандмауэр Windows:** разрешите входящие подключения на порт **8000**
   - При первом запуске Uvicorn обычно показывает окно с запросом — нажмите «Разрешить»
   - Если окно уже закрыто: «Брандмауэр Защитника Windows» → «Дополнительные параметры» → «Правила для входящих» → «Создать правило» → «Порт» → **TCP 8000** → «Разрешить»
2. **Одна сеть:** сервер и клиент должны быть в одной подсети (одинаковый префикс IP, например `192.168.1.x`)
3. **IP правильный:** в блоке «Исходящий плейлист» показан реальный локальный IP, а не `127.0.0.1`

### Ошибка 0xCFFFFFFF при выборе цвета

**Причина:** в старых версиях структура `CHOOSECOLORW` не обнулялась перед заполнением, что приводило к передаче «мусорных» указателей в Windows.

**Решение:** в актуальной версии `gui.py` это исправлено (используется `ctypes.memset`). Обновите файл из репозитория.

### Приложение зависает при добавлении оверлея

**Причина:** в старых версиях `start_overlay` вызывал `stop_overlay` внутри уже захваченного `Lock` — взаимная блокировка.

**Решение:** в актуальной версии используется `threading.RLock()` и немедленный старт через `DateTrigger` в потоке планировщика. Обновите `stream_engine.py` и `scheduler.py`.

### Исходящий плейлист содержит все каналы

**Причина:** в старых версиях `generate_server_m3u` не фильтровал по выбранным каналам.

**Решение:** в актуальной версии `PlaylistManager` хранит `broadcast_channel_ids` и фильтрует по нему. Обновите `playlist_manager.py` и `gui.py`.

## Структура проекта

```text
IPTV-Overlay-Server/
├── main.py                 # Точка входа — запуск QApplication
├── gui.py                  # Главное окно (PyQt6)
├── models.py               # Dataclass-модели Channel и Overlay
├── playlist_manager.py     # Парсер M3U, генератор исходящего плейлиста
├── stream_engine.py        # Управление FFmpeg-процессами, HLS
├── scheduler.py            # APScheduler + CronTrigger
├── server.py               # FastAPI-приложение
├── ffmpeg_manager.py       # Поиск/скачивание FFmpeg
├── README.md               # Этот файл
├── requirements.txt        # Зависимости
├── .gitignore              # Исключения для git
├── ffmpeg_bin/             # Сюда скачивается FFmpeg (создаётся автоматически)
└── hls_output/             # HLS-сегменты по каналам (создаётся автоматически)
    └── {channel_id}/
        ├── index.m3u8
        ├── segment_000.ts
        ├── segment_001.ts
        └── ffmpeg.log
```

### Описание файлов

| Файл | Назначение |
|------|-----------|
| `main.py` | Создаёт `QApplication`, `MainWindow`, запускает цикл событий |
| `gui.py` | Всё окно: меню, три панели, работа с цветом, календарём, сервером |
| `models.py` | `@dataclass Channel` и `@dataclass Overlay` — простые структуры без логики |
| `playlist_manager.py` | Парсит M3U вручную (без внешних библиотек), хранит `broadcast_channel_ids` |
| `stream_engine.py` | Запуск/остановка FFmpeg, работа с HLS, экранирование путей и текста |
| `scheduler.py` | `BackgroundScheduler` + `CronTrigger` + `DateTrigger`, проверка дат и дней недели |
| `server.py` | Эндпоинты `/playlist.m3u` и `/stream/{id}/{file}`, редирект при отсутствии оверлея |
| `ffmpeg_manager.py` | Проверка системного FFmpeg, скачивание сборки BtbN для Windows/Linux |

### Служебные папки

- **`ffmpeg_bin/`** — появляется при первом запуске, если FFmpeg не найден в системе. Содержит `ffmpeg.exe` (Windows) или `ffmpeg` (Linux). Можно удалить — при следующем запуске скачается заново.
- **`hls_output/{channel_id}/`** — создаётся при каждом запуске оверлея. Содержит HLS-сегменты и лог FFmpeg. Очищается при остановке оверлея.

## Технологии

| Технология | Назначение |
|------------|------------|
| **Python 3.10+** | Язык программирования |
| **PyQt6** | Графический интерфейс |
| **FastAPI** | HTTP-сервер с async-обработчиками |
| **Uvicorn** | ASGI-сервер для FastAPI |
| **FFmpeg** | Обработка видео, наложение текста (`drawtext`) |
| **APScheduler** | Планировщик расписания (`CronTrigger`, `DateTrigger`) |
| **ctypes** | Вызов нативного диалога выбора цвета Windows (`comdlg32.ChooseColorW`) |

### Особенности реализации

- **Парсер M3U** написан вручную — не зависит от внешних библиотек и их версий, работает с разными кодировками
- **Нативный диалог выбора цвета** — `ChooseColorW` через `ctypes` (на Linux/macOS — фолбэк на `QColorDialog`)
- **Нативный календарь** — `QDateEdit.setCalendarPopup(True)` использует системный `MonthCal` на Windows
- **`threading.RLock()`** в `StreamEngine` — предотвращает deadlock при вложенных вызовах
- **`DateTrigger` для немедленного старта** — не блокирует GUI при добавлении оверлея, попавшего в активное окно
